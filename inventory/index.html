What's on your belt

Grouped by the move each one makes. A table row can't teach a heap, so every entry carries a worked example and the mistake people actually make.

remember

Spend memory so you never compute the same thing twice.

Symptom: The inner loop is re-deriving a fact the outer loop already knew.

Hash map / set O(1) average insert and lookup

Answer "have I seen this?", "how many of each?", and "where is it?" without re-scanning. Solves more real problems than everything else here combined.

seen = {}
for i, x in enumerate(nums):
    if target - x in seen:
        return [seen[target - x], i]
    seen[x] = i

Watch out: O(1) is the average, not a guarantee — and keys must be hashable, so a list can never be a key while a tuple can.

Taught in unit 01

Counting & grouping O(n) to build

Tally occurrences or bucket items by a computed key. Turns "are these anagrams", "most common error", and "group by shape" into two lines.

from collections import Counter
Counter("mississippi").most_common(2)   # [("i", 4), ("s", 4)]

Watch out: Counter returns 0 for missing keys instead of raising, so a typo in a key reads as "seen zero times" rather than an error.

Taught in unit 01

Prefix sums O(n) build, O(1) query

Precompute cumulative totals so any range sum is one subtraction. Turns "sum of every subarray" from quadratic into linear.

pre = [0]
for x in nums: pre.append(pre[-1] + x)
range_sum = pre[j + 1] - pre[i]

Watch out: Off-by-one at the boundary. Keep the leading 0 and the formula stays `pre[j+1] - pre[i]` every time.

Taught in unit 04

Memoisation varies

One decorator that turns exponential recursion into polynomial. The highest-leverage line of code in this list.

from functools import cache

@cache
def climb(n):
    return n if n <= 2 else climb(n-1) + climb(n-2)

Watch out: It only helps when subproblems actually repeat, and the arguments must be hashable. `def f(x, memo={})` shares one dict across every call, forever.

order

Impose structure once, then exploit it many times.

Symptom: You keep asking for the smallest, nearest, or next larger thing.

Binary search O(log n)

Find the boundary in anything monotonic — where "no" flips to "yes" and never flips back. Sorted arrays are only the most familiar case.

while lo < hi:
    mid = lo + (hi - lo) // 2
    if ok(mid): hi = mid
    else:       lo = mid + 1
return lo

Watch out: Pick one template and never deviate. Mixing `<` and `<=` conventions between problems is how the off-by-one gets in.

Taught in unit 05

Binary search on the answer O(n log range)

When you can't compute the answer but can cheaply check a candidate — and any candidate that works implies all larger ones do — search the answer space itself.

# what am I searching over? what is the check? is it monotone?
lo, hi = max(weights), sum(weights)

Watch out: Skipping the monotonicity check. If a bigger candidate can fail where a smaller one succeeded, the search is meaningless.

Taught in unit 06

Heap O(log n) push/pop, O(1) peek

Repeatedly get the current smallest or largest while the set keeps changing. Top-k, merging streams, schedulers.

import heapq
heap = []
for x in stream:
    heapq.heappush(heap, x)
    if len(heap) > k: heapq.heappop(heap)   # keeps the k largest

Watch out: A heap is not a sorted list. Only `heap[0]` is meaningful — printing the rest looks scrambled because it is.

Taught in unit 08

once

Touch each element a bounded number of times.

Symptom: Nested loops where the inner one never needs to go backwards.

Two pointers O(n)

Not a data structure — a discipline. Two indices that only move forward, so the array is covered in one pass instead of n passes.

lo, hi = 0, len(a) - 1
while lo < hi:
    s = a[lo] + a[hi]
    if s == target: return (lo, hi)
    if s < target: lo += 1
    else: hi -= 1

Watch out: It needs sortedness (or some other reason the discarded side cannot hold the answer). On unsorted input the argument collapses.

Taught in unit 02

Sliding window O(n)

Best contiguous run satisfying a constraint. Expand right, shrink left while violated, record the answer.

L = best = 0
for R, ch in enumerate(s):
    while ch in window:
        window.remove(s[L]); L += 1
    window.add(ch)
    best = max(best, R - L + 1)

Watch out: Only valid when shrinking can actually fix a violation. Introduce negative numbers into a sum constraint and the window silently returns a wrong answer.

Taught in unit 03

structural

Doesn't speed anything up alone — it makes a single pass possible.

Symptom: You need to process something later, in a particular order.

Stack & monotonic stack O(1) per push/pop

"Deal with this later, most recent first." The monotonic variant answers "next greater/smaller element" for every position in one pass.

for i, x in enumerate(nums):
    while stack and nums[stack[-1]] < x:
        res[stack.pop()] = x
    stack.append(i)

Watch out: Decide up front whether ties count: `<` versus `<=` silently changes the answer on inputs with duplicates.

Taught in unit 07

Queue / deque O(1) at both ends

"Deal with this later, oldest first." BFS, sliding-window maxima, ring buffers.

from collections import deque
q = deque([start]); q.popleft()

Watch out: `list.pop(0)` is O(n) and turns a linear scan quadratic. Use `deque.popleft()`.
